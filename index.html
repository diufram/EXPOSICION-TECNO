Fundamento

¿Que es TypeScript y de donde surge?

TypeScript es un lenguaje de programacion de codigo abierto desarrollado por Microsoft (liderado por Anders Hejlsberg, disenador de C#). No busca reemplazar a JavaScript, sino complementarlo dotandolo de robustez para proyectos de gran escala.

Es un Superset Tipado

Todo codigo JavaScript valido es codigo TypeScript valido. Anade una capa formal de sintaxis para tipos estaticos sobre JavaScript sin alterar la esencia del lenguaje.

El Proceso de Transpilacion

Los motores como V8 y Node.js ejecutan JavaScript. El compilador (tsc) valida los tipos en desarrollo y transpila a JavaScript nativo limpio y universal.

Cero Costo en Tiempo de Ejecucion

Los tipos existen unicamente en el editor. En produccion se eliminan por completo, garantizando que el rendimiento de ejecucion sea 100% nativo.

Diferencias Clave

¿En que se diferencian en el dia a dia?

Tres ejemplos simples para ver como nos ayuda TypeScript al escribir codigo:

1. Cambiar numero por texto

JavaScript 
let edad = 20;
// Permite guardar texto sin avisar:
edad = "veinte";
TypeScript 
let edad: number = 20;
// No deja guardar texto en un numero:
edad = "veinte";

En JavaScript puedes cambiar un numero por texto sin darte cuenta y dañar calculos. TypeScript te avisa al instante para evitar errores.

2. ¿Cuando descubres el error?

JavaScript 
const perfil = null;
// Falla cuando el usuario ya esta en la web:
perfil.email;
TypeScript 
const perfil: Perfil | null = null;
// Te marca el error en rojo al programar:
perfil.email;

En JavaScript el error aparece cuando la aplicacion ya esta funcionando frente al usuario. En TypeScript te lo muestra antes de guardar.

3. Ayuda al escribir (Autocompletado)

JavaScript 
// Tienes que recordar los nombres de memoria:
pedido.
TypeScript 
// Te sugiere los datos exactos al poner el punto:
pedido. // id | cliente | total | fecha

En JavaScript tienes que acordarte de memoria como se llamaba cada dato. En TypeScript el editor te sugiere las opciones correctas al instante.

Bondades Visuales

¿Por que usar TypeScript en la Industria?

Los cuatro pilares de productividad y calidad de software respaldados por ejemplos claros:

1. Modelos Claros (Saber que contiene cada dato)

JavaScript 
// No hay forma de exigir que datos debe llevar:
const usuario = {
  nom: "Carlos", // ¿era 'nom' o 'nombre'?
  correo: "carlos@mail.com"
};
TypeScript 
// La interfaz define la forma obligatoria:
interface Usuario {
  nombre: string;
  email: string;
}
const usuario: Usuario = { nombre: "Carlos", email: "carlos@mail.com" };

En JavaScript cada quien puede inventar nombres diferentes para los mismos datos. En TypeScript el modelo queda acordado para todo el equipo.

2. Escribir mas rapido con sugerencias (IntelliSense)

JavaScript 
const server = { puerto: 3000, host: "localhost" };
// El editor no sabe que opciones ofrecerte:
server.
TypeScript 
const server = { puerto: 3000, host: "localhost" };
// Te sugiere las opciones exactas con un clic:
server. // sugiere: puerto | host

En JavaScript pierdes tiempo revisando otros archivos para ver como se llamaba una opcion. En TypeScript el editor te la sugiere al instante.

3. Cambiar nombres sin romper el proyecto

JavaScript 
// Si cambias 'total' por 'montoTotal',
// JS no avisa y otras partes del codigo
// seguiran buscando 'total' fallando en silencio.
TypeScript 
// Al cambiar 'total' por 'montoTotal',
// TypeScript marca en rojo cada archivo
// del proyecto que necesite actualizarse.

En JavaScript modificar un sistema grande da miedo porque puedes romper cosas sin saberlo. TypeScript te indica exactamente que archivos actualizar.

4. Evitar fallas en calculos y operaciones

JavaScript 
// JS une texto con numero:
const cobro = "100" + 20;
console.log(cobro); // Da "10020" en vez de 120
TypeScript 
function cobrar(precio: number, envio: number) { ... }
// Error inmediato en rojo en el editor:
cobrar("100", 20); // No permite texto

En JavaScript sumar texto con numeros junta las palabras y genera cobros erroneos. TypeScript te bloquea antes de que el fallo llegue al usuario.
